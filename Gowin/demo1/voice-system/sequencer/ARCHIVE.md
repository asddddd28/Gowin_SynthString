# 编号音序库、SD 预设与 RAM 交换约定

阶段：建立可验证的保存格式和 RAM 导入/导出接口。板上的首个音序器版本仍仅保存于 RAM；本文件不是 SD 自动保存已经完成的声明。

2026-11-03 进度补充：`../storage/INTEGRATION.md` 记录新增自主 SD 块读写、受限 exFAT 目录挂载、参数读回、归档传输及保存会话的验证。保存会话已与实际音序器 RAM 联调仿真通过；整机只读挂载候选在布线阶段失败，尚未烧录，实体按钮及完整加载尚未连接。下文的阶段描述是原协议基线，不能据此推断 SD 已可用。

## 用户确认的操作与目录

- SW1 录制/结束；SW2 清空当前 RAM 工作区；SW3 在录制结束后手动保存；SW4 播放/暂停；SW5/SW6 前后切换已存音序，首次定位最新有效编号。BPM 在 App 设置。SW2 不删除 SD 文件。
- 音序文件：`SEQUENCES/00000001.SSQ`、`00000002.SSQ`……，每次保存使用新编号，不覆盖旧文件。删除需确认，编号不回收；损坏/中断文件不参与正常回放，但仍占用其编号。
- 预设文件：`PRESETS/00000001.SSP`……，由 App 提前传入；包含名称、单音色参数页、完整波表、ABI/版本和 CRC。
- HDMI 页6为音序库，页7为SD音色库；上下/E2选择，短按摇杆载入，E1选择目标Slot，E5仍控制总音量。SW5/SW6始终作用于音序库。长按摇杆仍切换触摸演奏模式。
- 切换/载入音序不能静默丢掉未保存录音。载入预设不能覆盖录音保留槽，也不能替换其他录音层依赖的共享波表。当前4槽/单对共享波表限制不因有SD而消失。

`numbered_library.py` 已实现编号目录、列表/最新选择、载入、删除墓碑、预设上传/读取的离线模型。它通过实际 exFAT 目录解析与分配位图检查，递归拒绝交叉分配，并允许已验证的碎片链。只写预先分配、完整初始化的文件数据区，不写目录/FAT/位图。**尚缺 App 文件预分配/设备块驱动以及 FPGA 独立文件定位器；这不是已经可以用实体SW3保存的版本。** 不要把预分配的空条目显示成已保存录音。

## 音序文件与掉电提交

每个 `.SSQ` 文件33280字节（65个512字节扇区）。保存先验证目录项集合校验、完整初始化长度及分配范围，再写新文件；禁止以固定裸LBA代替文件定位。格式化和文件分配是独立准备操作。当前参考实现只接受512字节逻辑扇区、8层以内ASCII目录树和最多4096个文件/目录项；未知布局拒写。

相对扇区 0 为提交头，1..64 为正文。正文内偏移：0 全局控制页；512..2559 四个音色页；4608..16895 为至多 1024 个 12 字节事件；16896..25087 为 2048 个 signed Q26 波表点。其余字节置零。

每个音色页 512 字节：0 处 valid u32；4..15 保留；16..159 为六个 A1 的各六字；160..351 为六个 A2 的各八字；352..391 为两个 B0 的各五字；392..455 为八个 B1 的各两字；456..503 为 UTF-8 名称；504..511 保留。保存实际参数，不保存不可跨启动复用的 A0 revision；恢复时重新取得 revision 并按 A0 / A1 / A2 / B0 / B1 / A3 装载。全局控制页的具体字段还需与固件读回接口一起定版，当前参考模型将其作为固定长度的不透明数据。

文件头：magic `SYSEQAB\0`，版本、文件长度、64 位代数、正文长度、正文 CRC32、BPM、循环 tick、事件数、使用槽掩码、PPQ=960、DSP ABI=0x10007；56..507 保留零；508..511 为头部前 508 字节 CRC32。所有整数小端，CRC 为 ISO-HDLC（与 zlib.crc32 一致）。

保存顺序：选择最大已使用编号+1 → 写暂存标记保留该编号 → 按扇区写正文且逐扇区读回 → 验证整个正文 → 最后写提交头且读回。内部代数必须等于文件名编号，禁止回绕。旧的有效文件始终不写。删除使用带CRC的墓碑头，软件界面隐藏墓碑，但不悄悄复用文件编号。新文件损坏时，之前保存的文件仍可正常选择。

旧 `archive_model.commit` / `archive_files.py` 的根目录A/B双文件方案保留为故障注入测试基线，**已不是用户选择的目录方案**。原A/B模型覆盖67个中断位置×4种扇区撕裂长度；编号方案另测中途断写不覆盖前一文件、损坏跳号、删除、重挂载后最新选择。二者均不能替代真实拔电测试或保证SD内部FTL的掉电行为。

`.SSP` 预设为9216字节（18扇区）：512字节提交头、512字节音色页、8192字节完整Q26波表。头为 `SYPRESET`、版本1、文件长度、正文CRC32、ABI；32..79为48字节UTF-8名称，508..511为头CRC32，其余保留零。预设内容校验通过后才可装载；先配置音色/波表，取得实际硬件确认后再更新当前Slot显示。

## RAM 交换接口设计

复用事件 RAM 的读写口，不复制五块事件 RAM。只有停止录制、暂停播放且回放 Note-Off 清理完成后，才允许取得导出/导入租约；租约期间阻止实体按钮和 App 改动录音/速度，并锁住音色页。现场演奏和 PCM 继续工作。

导入只能写空工作区，以免半包覆盖现有录音。先按顺序写完整事件，再一次性发布数量、完整小节长度和 BPM；任何中止均不发布部分事件。事件包保持现有 90 位布局；文件中高六位为零。导出按索引返回同一代的事件；无活动租约时不能读取未初始化 RAM。

FPGA RAM 交换接口现已实现（`SynthSequencer.v` 的0x43..0x48），`tb_sequence_archive` 和真实UART/AXI/PT8211系统仿真通过。运行时仅做有限的字段/索引校验；Rust 导入前还检查 Note-Off 必须指向更早的 Note-On。所有事件在计数发布前不可回放，取消不会发布半份数据。

0x41 状态响应高字 bits 127:124 新增已保存录音的实际音色槽掩码，其余 bits 123:116 保留零、bits 115:96 仍为回放位置。该掩码在导出期间保持真实依赖；低字 bits 11:8 表示当前锁定槽，此时会成为 0xf，不可把它当成归档依赖掩码。

新版 `numbered_library.py` 支持两个子目录；`exfat_reference.list_directory` 不改变根目录索引，并按EOD提前结束读取。组合测试证明多次编号保存、删除、预设上传只改目标文件数据，`KEEP.TXT`与文件系统元数据不变；地址测试覆盖4GiB以上字节地址。此层仍是参考模型，尚未综合为FPGA文件定位器。
