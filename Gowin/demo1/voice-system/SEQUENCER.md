## 首音窗口与连续回放修复

按SW1立即启动节拍并等待首个Note-On。首音所属的四拍窗口前移`floor(BPM*8/25)`个tick，120BPM时为38/1920秒，即19.79ms。20..300BPM范围内实际提前量不超过20ms，量化误差小于一个tick。这只调整事件记录坐标，现场琴键仍走原来的声音通路。

首音之前的空小节不再计入循环；开始边界当拍归新小节。结束时仅保留完整窗口，并去除最后演奏之后的纯空小节；夹在两段演奏之间的休止保留，持续按住的长音不会当成空白裁掉。已有循环的叠录长度和导入音序不自动裁剪。仍不足一整个有效窗口时不生成循环。

`record_window.py`给出独立区间语义；`tb_record_window.v`在原模块复现了本应只保留256tick却保留768tick的案例。修复后覆盖边界前/当拍/后、首音/松键恰与tick同拍、首尾空白、持续长音、中间休止和四轮播放周期。281种BPM偏移全部验证。首次录制状态bit6表示等待首音，App显示“等待首音 · 节拍已开始”。包络/音频采样频率未改，提前量计算不使用DSP、除法器或新增事件RAM。

## 操作

| 控制 | 行为 |
|---|---|
| SW1 / App 开始录制 | 第一拍立即开始，重音“嘀”、另外三拍“哒”；只记录实体琴键与触摸拨弦的接受事件 |
| 再按 SW1 | 丢弃当前未完成小节；保留 n×4 拍并自动循环。少于一小节不生成循环 |
| 有循环时 SW1 | 沿已有循环长度叠录，再按结束；此前内容继续播放 |
| SW2 | 清空 RAM 录音、停止录放、释放音色槽；仅释放回放的 NoteID，现场按键继续 |
| SW3 | 保存请求；SD执行器未启用时不会保存文件，App明确提示 |
| SW4 | 暂停 / 从循环开头播放；录制期间不可暂停 |
| SW5 / SW6 | 上一条 / 下一条请求；SD音序库读取尚未启用 |
| App BPM 设置 | 20～300；旧能力1固件仍按SW3/4调速度，App按版本显示 |

六个按钮沿用 `demo_test/diagnostics/hardware_hdmi/src/hdmi.cst` 的 AA19、AB18、Y18、N15、U17、P15。高有效，5 ms 消抖。App 状态页提供同样的控制、节拍位置、事件数量和保留槽显示。

换音色叠录时先结束当前层录制，选择新音色，随后再次开始。App 自动避开已保留槽；最多四种驻留音色。主滤波器、触摸调制和主输出增益仍共享，尚无每层独立后级处理。所有回放与现场演奏共用八个发音声部，超过时使用原引擎的抢占策略。

音色容量提示现区分现场琴键引用与录音保留：没有录音占用时，建议扩大应用范围或合并键位音色，不再误导用户清空音序；有录音时列出具体保留槽。暂停回放不会释放保留槽。音色预检先读回板卡当前占用，避免实体SW2清空后仍按旧缓存拒绝。已有相同音色可直接复用，不另占槽。App 79项Rust测试通过，安装后已重新连接COM4；当前所有32键恢复为AM芦管、音量37%、触摸仍为原来的吉他模式。

## 数据与调度

```text
六按键 ─ TactileInput ×6 ─┐
App / UART 本地指令 ──────┼─ SynthSequencer ── 回放 A4/A5 ─┐
键盘/拨弦 ─ KeyboardSource ─ 仲裁器接受时旁路记录          │
                         └─ 5×1024×18 事件 RAM           │
Boot / 现场键 / App ──────────────────────────────────────┼─ CommandArbiter
                                                        └─ AxiMaster
                                                           → AXI → VoiceEngine
SynthSequencer → SynthMetronome → 饱和混音 → PT8211 DAC
                                   └→ 寄存一级 → HDMI 波形/频谱分析
```

音序器在50MHz系统域用1μs分数累加器生成960PPQ节拍；改变BPM不清音乐位置。计时不依赖AXI完成，但音符仍要排队进入原硬件命令通路。扫描已提交事件的时间窗口，避免背压期间静默遗漏某个tick。

1024个90位事件含tick20、配对anchor10、phase32、velocity7、note7、slot2、开关/力度模式各1、key5与保留位5。拆成五个18位RAM；至少预留32条用于截断长音时补NoteOff。容量不足时自动结束录制，保留最后完成的小节并上报满标志。

每个小节边界保存写指针、按住位图、32个配对索引和槽位集合。停止后回滚未完成小节。循环边界、暂停和清空只清理音序器自身ID；回放ID高四位为4，实体键盘ID高位为8。

仲裁器运行期轮询现场键、App、回放三个来源，仍只有一个已发出且等待回执的命令。VALID等待READY期间保持整包稳定。AxiMaster在写入前拒绝覆盖保留的A0/A1/A2/A3音色和A8全局波表，返回状态11，不污染全局fault或下游指令序号。

## 串口接口

沿用52字节CRC请求与32字节回复，kind=3，argument=0。

| Opcode | 请求 | 回复低四字 |
|---|---|---|
| 0x40 | 全零 | magic=0x53455131、能力版本、容量、PPQ；1=旧按键，2=新按键/库请求，3=提前窗口与首尾裁剪 |
| 0x41 | 全零 | flags、BPM与事件数、循环tick数、当前tick |
| 0x42 | word0=1录制翻转/2清空/3播放翻转/4BPM；word1仅BPM时使用 | 操作接受状态，随后读0x41确认实际状态 |
| 0x43 | 全零 | 快照能力 `ARC1`、租约模式、暂存事件数、事件宽度90 |
| 0x44 | word0=索引；word1=0 | 三字90位事件（高六位零）、32位工作区代数；仅导出租约有效 |
| 0x45 | word0=1取得导出租约、2取得导入租约、0结束/中止；word1=0 | 仅停止录制/播放且清音结束时可取得；导入还要求空工作区 |
| 0x46 | 事件低64位 | 导入暂存半包，不增加事件数 |
| 0x47 | word0=事件高26位、word1=从0递增的事件索引 | 完整事件写RAM；拒绝保留位/顺序/配对索引错误 |
| 0x48 | word0低16位=数量、高16位=BPM；word1=完整四拍小节数 | 一次性发布元数据，恢复后保持暂停 |
| 0x49 | 全零 | SW3/SW5/SW6累计事件数（各字低16位），工作区代数；它们不是SD成功回执 |

flags bit0录制、1播放、2截断收尾、3满、4回放故障、5快照租约、6等待首音；bits11:8保留槽，bits21:16实体按钮。BPM与事件数分别在word1低16位和高16位。重复串口包由原Host重放缓存处理，不会重复执行翻转操作。

0x43..0x48 是本轮新增的源码能力，首个已烧录版本尚无这些指令。导出/导入复用事件 RAM，租约期间锁住四槽和录放/BPM控制，约42.95秒没有快照命令则自动释放。UART 未确认请求必须先原样恢复，后台不能跳过并发新包。Rust `sequence_export` / `sequence_import` 是诊断接口，仅传事件；它们不等同于包含音色/波表的 SD 存档，不在普通界面提供“已存SD”按钮。
