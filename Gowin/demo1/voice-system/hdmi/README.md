# SynthUI HDMI 显示与控制

2026-11-04：当前顶层新增 `SynthKeyboardRgb`，使用现有实体按键状态驱动 R19 上的 32 颗灯；SD 控制器按用户要求停用。见 [键盘 RGB 与验证记录](../KEYBOARD_RGB.md)。

以 `Gowin/SynthUI` 的六页布局、配色和原始 5×7 字库为依据，在 Tang Mega 60K 上生成 1280×720 画面。使用 12×16 字符格、图形叠加和共享行 ROM；不是浏览器截图，也不占用完整 RGB 帧缓冲。

## 已接通的通路

```text
SynthHdmiTop
├─ SynthSystemTop                    50 MHz，原键盘 / AXI / Voice Engine / PT8211
│  ├─ KeyboardSampler + Thresholds   实体32键
│  ├─ Boot / Keys / UART → Arbiter → AXI Master → Voice / LFO
│  ├─ SynthPcmOutput                48,828.125 Hz，16-bit 双声道
│  └─ SynthStudioMonitor            映射、PCM快照、按键调度至数字输出延迟
├─ SynthDisplayControl              五编码器、摇杆、UART本地命令
├─ SynthDisplaySnapshot             握手快照、延迟转十进制微秒
├─ SynthDisplayAudio                PCM副本 → 64频点DFT、波形双缓冲
├─ SynthDisplayVideo                六页文字、32键、波形、频谱、历史图
├─ TMDS_PLL                         73.333333 / 366.666667 MHz
└─ DVI_TX_Top                       HDMI接口视频输出
```

主音频时钟仍为 **50 MHz**。720p 总时序为 1650×750，实际刷新率约 **59.259 Hz**；使用已经在本底板验证过的 PLL/DVI IP 和 TMDS 管脚。HDMI 不携带音频，声音仍从底板 3.5 mm 耳机口输出。

显示分析没有 `ready` 返回主音频通路。DFT 每个采样最多使用448个50MHz时钟，处理64个频点；显示消费不及时只丢弃观察窗口，不阻塞音频。双缓冲在垂直消隐发布，样本存储与跨域请求/应答均独立于主 DSP。

## 页面与实际能力

| 页面 | 当前内容 |
|---|---|
| Overview | 实体32键、256点真实PCM波形、64频点频谱、64×64历史图、4个音色槽、数字延迟及欠载 |
| Patches | 当前4个驻留音色名称与槽位；预设载入仍从App音色浏览器操作 |
| Operators | 当前槽/算子的FM或Native参数、比率/固定频率、EG、调制源等 |
| Modulation | 硬件LFO能力说明；当前合并App尚未提供完整LFO状态适配，不显示虚构参数 |
| Effects | 当前固件没有Delay/Reverb，明确显示未编译 |
| System | 时钟、采样率、按键位图、真实错误/帧计数、控制说明 |

这是第一版硬件显示实现，**没有完整复刻 SynthUI 的全部交互**：未做图表放大、真实算法拓扑图、屏幕上全参数编辑、独立音色库浏览。当前字库为ASCII，中文原生音色名在HDMI上使用波形/模式名称；App保留中文。

波形按本次冻结窗口峰值选择1～128倍显示增益，幅值低于64个PCM计数时保持原比例，避免放大数字底噪。此增益不进入音频处理。频谱为256点窗口的64个DFT频点，范围 **190.735 Hz～12.207 kHz**；使用近似对数幅度，不是标定功率测量仪。后续可扩展更长窗口与低频对数频轴。

波形稳定采用**带迟滞的上升沿触发**：先观察到小于负阈值的PCM，再在向上过零时开始记录连续256点，避免不同显示帧从任意相位开始。阈值取上次窗口峰值的1/16，最低4个PCM计数；最长等待2048个采样（约41.94ms），静音/直流/信号大幅变弱时自动触发以保持刷新。这只延迟显示窗口的获取，不延迟合成或DAC输出。波形和DFT来自同一连续窗口，不循环拼接首尾。和弦、噪声和复杂FM仍可能变化；最低MIDI音符的周期不一定是所有叠加信号的共同周期。

App的“触发稳定”默认打开，在512点硬件快照内寻找上升沿，并显示随后连续256点（5.24ms）；没有可用过零时自由显示，不伪造稳定波形。关闭后显示原始512点（10.49ms）。频谱继续用原始512点进行Hann窗FFT，时间/频率标尺不随触发裁剪混淆。低音周期长于快照时，App无法保证每次找到过零；HDMI在连续PCM中等待触发，覆盖更长周期。

## 实体与App操作

**Slot是FPGA中驻留的一整份音色程序与参数。** 当前4个Slot独立保存各自的六算子配置；32个琴键各有“Slot、MIDI音高、力度”映射。多个键可以共享一个Slot而以不同音高发声，总复音仍为8。E1只选择编辑目标，不修改琴键的Slot映射、不自动给所有键换音色；切换键所使用的音色应从App声音设计/音色浏览器载入。确认修改一个Slot会影响所有映射到它的键。

| 输入 | 操作 |
|---|---|
| 摇杆左右 | FPGA本地切换六页，脱离App也有效；拨一次切一页，回中/长按不重复 |
| 摇杆上下 | App连接时选择上一/下一算子 |
| E1 | 选择音色槽；各槽草稿在本次连接内独立保留，不再阻止切槽 |
| E2 | 选择六个逻辑算子 |
| E3 | FM输出电平 / Native算子增益，先写草稿 |
| E4 | 比率模式下调整频率比，先写草稿；固定Hz模式不改变频率 |
| E5 | 主音量，实时发送已有控制命令 |
| 摇杆按下 | 松键、关闭延音后应用草稿，影响共享当前槽的琴键 |
| App“设备与输出” | 选择HDMI页面、应用/取消旋钮草稿 |

每格E3变化为DX输出1级（0..99）或Native增益1%；E4变化为0.25倍，Native范围0..16、DX范围0..64；E5变化为主音量1%。E3作用于载波时主要改变响度，作用于调制算子时会改变调制强度和音色；E4改变的是选中算子的频率比，1倍等于键的基频、2倍为其两倍频率。E2选到未启用的算子时，调电平不会将它自动启用。

**旋钮参数编辑由App桥接，需保持连接。** FPGA独立运行的是画面生成、真实音频分析、亮键和左右翻页。完全脱机编辑还需要FPGA内的参数影子表、草稿提交器及主控制器命令仲裁；本版没有假装已完成这部分。App连接心跳超过2秒未到，屏幕会显示离线。

屏幕底栏和实物从左到右一致：**E5 主音量、E4 频率比、E3 电平、E2 算子、E1 音色槽**。这是位置顺序调整，不改变编码器A/B相序。App“旋钮输入诊断”显示对应FPGA累计边沿计数；每格约4边沿。应用/取消只处理当前槽，退出或断开前应应用需要保留的草稿。App重新载入某槽时，旧版本草稿会清除，其他槽不受影响。

输入引脚沿用 `demo_test/diagnostics/hardware_hdmi/src/hdmi.cst`。五个编码器A/B依次为 AA20/AB21、Y21/U20、N13/N17、W21/V17、R18/P16。摇杆XH/XL/YH/YL为R14/R16/U18/T20，按压P14；保持原电气顺序。每轴按bit0=H、bit1=L解释：00低区、01中位、11高区、10异常。X低区向左、高区向右；Y高区向上、低区向下。上电需先见中位才能触发，异常组合不发动作，斜向优先左右。原先把四个比较器当独立方向按钮的逻辑已替换，不能用简单交换H/L引脚代替方向解码。

## 串口与状态一致性

复用协议5的52字节请求、32字节响应以及原有CRC、持久序号与完全相同包的缓存重放，不打开第二个串口句柄。

| kind=3 opcode | argument / words | 功能 |
|---|---|---|
| `0x10` | 全零 | 能力：`HDM1`、接口`0x10000`、像素时钟、文本容量 |
| `0x11` | argument=0..5，words零 | 切页，下一帧快照显示 |
| `0x12` | argument=0..127，words=8字节ASCII | 写入1024字节元数据区；8个写边沿完成才应答 |
| `0x13` | 全零 | 五路16位绝对编码器计数、page、focus、16位确认次数 |

输入使用绝对计数；主机对比差值，不以“读取即清除”消费事件，避免重试造成重复旋转。编码器进行两拍同步、50µs滤波及Gray合法性检查；摇杆5ms去抖。元数据差量更新，每个后台操作最多传一个文本块；波表传输时暂停显示元数据同步。文本块可能在当前帧可见，不保证跨多个块的整个编辑器原子刷新；音频与硬件状态快照不受影响。

## 构建、测试与证据

在本机使用已安装的 Gowin 1.9.11.03 Education、Vivado xsim 和Rust/Tauri工具链。所有候选项目冻结到 `../reports/synthui-hdmi/`，不覆盖原已验证的 `unified-studio` 位流。

1. `node hdmi/model/prepare_assets.mjs`：从SynthUI字库编译共享字符ROM。
2. `python hdmi/model/prepare_validation.py`：独立参考模型与测试输入。
3. xsim运行 `tb_display_audio`、`tb_display_control`、`tb_display_video`，原整机运行 `tb_studio_system`。
4. `python hdmi/model/build_hdmi.py <候选目录>`，在输出目录运行Gowin的`build.tcl`。
5. 检查Gowin实际setup/hold和所有时钟Fmax，再运行`program_hdmi.py <候选目录>`。该脚本仅进行**SRAM**烧录。

实际证据：

- `sim/audio.log`：相移正弦、弱信号、静音、直流、30.5Hz低频共448个对数频点和1792个波形值逐项匹配Python模型；触发对齐、超时自动刷新、自动缩放与异步发布。
- `sim/control.log`：命令边界、文本应答、6700µs十进制CDC、五编码器读回、摇杆左/中/右、上下、保持/释放/异常输入/上电按住、确认去重。
- `sim/video.log`：六页各921600有效像素，无未知RGB，HS/VS宽度正确；`.ppm`来自真实RTL仿真。
- `audio-regression.log`：原键盘映射、CRC重放、512点PCM逐项一致、数字延迟通路。
- `board-result.json`：真实COM4上单声部/8声部、六页命令、元数据与音频遥测；恢复用户4音色、波表和32键映射。
- `timing.json`、`programmed.json`：最终实际构建时序和烧录SHA256，以文件记录为准。
- `rust-tests.log`、`ui-tests.log`：Rust与统一App回归。
