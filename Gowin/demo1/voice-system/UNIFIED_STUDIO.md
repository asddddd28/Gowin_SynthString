# Tang Synth Studio：统一按键工作台

运行 `app/TangSynthStudio.exe`。固件为本目录 `reports/unified-studio/build/impl/pnr/synth_studio.fs`，50 MHz、干声，2026-11-03 已完成 SRAM 烧录与串口实测。普通重连不要选择“建立新会话”；只有板卡烧录或复位后才使用新会话。

## 操作流程

1. **状态显示**为首页：显示 32 键的音高、当前音色、实体按下状态，以及活动声部、DSP 时间和异常计数。点击键名进入该键的声音设计，按住键底部 ▶ 试听。电脑快捷键为 `1…8 / Q… I / A…K / Z…,`，按键上的提示与实际映射一致。
2. **声音设计**保留双振荡器、波形、旋钮/滑杆、包络与音键配置。FM1 音色显示实际六算子电平，完整参数通过“六算子配置”弹窗编辑。切页保留草稿，点“应用到硬件”后才生效。
3. **选择预设音色**跳到音色浏览器；基础预设与 FM1 Convert 共用同一条 Voice 协议和按键映射。成功后返回声音设计。侧栏快速载入也走这条通路，不再调用旧协议。
4. **应用范围**可以选择当前键、共享此音色的键、全部 32 键。硬件最多同时保留 4 种不同音色、8 复音。当前键与其他键共享音色时，优先分配未被按键引用的空间；没有空间就报错，不静默覆盖其他键。使用同一份已有音色无需额外空间。
5. **演奏控制**在状态页展开：主音量、力度、延音、临时移调、MIDI 输入及大小三和弦试听。主音量即时同步；音色参数可选“松键后自动同步”，失败时自动关闭，避免不断重试。切页或失焦释放 App 音符。实体键独立运行。

旧版工程切换、独立驻留音色栏已移除。旧配置文件仍保留在本机，未删除。旧的 32 键协议、PCM/SD 功能未伪装成当前 Voice 固件功能。

## 触摸板演奏

新增强度、音高、Cutoff 和四弦吉他模式，长按摇杆 0.8 秒切换；灵敏度在设备与输出页配置。使用说明与当前资源、验证数据见 [TOUCH_PERFORMANCE.md](TOUCH_PERFORMANCE.md)。

## 波形、频谱与延迟的含义

- 波形来自 **PT8211 数字输出边界上的真实左声道 signed16 PCM**，不是振荡器示意或电脑参考音。每次读取冻结的 512 点，48,828.125 Hz，窗口 10.49 ms。
- 频谱由同一份数据去除直流、加 Hann 窗并做 FFT。频率分辨率约 95.37 Hz，不适合区分很接近的低音基频。波形“自动范围”仅放大显示，不修改声音或 dBFS 读数。
- 115200 串口读取 512 点实测约 **1.1 秒**；GUI 还要让出按键与状态命令的时隙，因此不是逐帧连续流。界面显示更新时间，过期数据会标明。每次只排一个采样块，按键不需等完整快照。
- 延迟从键源准备 Note-On 到对应 PCM 帧进入 DAC 数字接口，使用帧标签关联；不包含 ADC 扫描/去抖、模拟电路、耳机声学和包络起音时间。同一时刻只追踪一个键事件，其他键正常发声。串口往返是另一个指标。
- 声音仍为 50 MHz / 1024 ≈ 48.828 kHz、16-bit 双声道，未改为 96 kHz/24-bit。

## 音色与资源限制

- FM1 Convert 保留 128 条目录，目前 21 条通过现有适配验证，其余显示具体限制并禁用载入。
- 16 个基础预设均经真实 Rust Native 编译器校验。旧 FM 深度转换到当前定点范围，包络使用满量程线性斜坡时间；不承诺与旧硬件引擎逐样本一致。采样播放器未纳入当前 Voice 固件。
- 波表仍是全局共享的 2×1024 点，上传会停音，完整确认后恢复；上传任务跨页面保留，所有页面均显示进度和暂停/继续入口；断线后从已确认位置继续，基础预设目标保留到完整上传后应用。引擎明确返回忙时，清理停音期间新占用的声部并重试同一点；通信结果不确定时只恢复原包。替换会影响其他使用波表的键，界面明确说明。
- 物理键表在 FPGA 中存储音色索引、相位增量、MIDI 音高和固定力度。按住时修改配置不重触发，松开沿使用原 Note-ID，再按才用新配置。

## 验证与构建证据

`reports/unified-studio/` 包含旧源文件备份、独立构建快照、输入 SHA256、仿真、实板日志与 UI 截图。

- 原整机回归：134 次 UART 回复、32 键、8 声部压力、PT8211，满载 878/1024 时钟。
- 新整机测试：本地命令 CRC/重放、逐键映射、持键改映射后的松键、512 点与 DAC 量化值逐点一致、帧标签延迟；测试观测 1841 clocks = 36.82 μs（仿真样例，不代表所有实板键事件）。
- 实板：PM/AM/Ring 与 FM1 GUITAR1、映射回读、容量拒绝保持原映射、已有音色复用、断线重连；无重试、坏包、欠载或超期。测试后恢复测试前默认配置。
- 人工验收（2026-11-03）：随后通过新版 App 将 K01 改为“正弦贝斯”、K02 保持 PIANO 2，用户交替按实体键后确认“音色不同，亮键正常”。此次确认覆盖这两个实体键的音色区分与状态页对应亮键，不代表所有预设均已人工试听。
- 初版 Rust 51 项测试通过；端到端界面测试覆盖真实基础资源解析和 Native 编译、模拟串口路由交互、草稿跨页、六算子弹窗、128 条目录、键盘去重/松键、FFT 数值与小窗口滚动。UI 测试中的板卡为显式模拟，实板证据单独记录。
- Gowin：CLS 22297/29952（75%），BSRAM 66/118（56%），DSP 58/118（50%），Fmax 50.001 MHz，报告无 setup/hold 违例。余量很小，后续 RTL 改动必须重新完整实现。
- 已运行 readable-verilog strict gate；格式器无法规范化当前紧凑 ANSI 端口写法，且有既有风格/规范问题，报告 `delivery_ready=false`。不能将这份风格门禁报告称为通过。实际 RTL 编译、仿真、Gowin 实现和实板验证分别提供了独立证据。

板级协议及测量边界见 `UNIFIED_STUDIO_CONTRACT.md`，接口与 WaveDrom 规范在 `spec/*_spec.md`。

## 桌面发布

在 `demo1/desktop-tauri` 执行 `npm run desktop:build`，或使用 Tauri CLI `build --no-bundle` 后复制 EXE 和完整 `assets`、`licenses` 目录。不能直接使用未启用 `tauri/custom-protocol` 的普通 `cargo build --release` 作为桌面发布：它仍会尝试访问开发服务器。已实际打开正式包并通过 COM4 从侧栏载入“正弦贝斯”，确认 K01 改为该音色，K02 及其他键保持 PIANO 2。

本次固件写入 SRAM，断电会丢失；重新上电若回到旧固件，需要重新烧录本次 `.fs`。普通断开/重连 App 不需要重新烧录或建立新会话。

## FM1 与波表修复更新

2026-11-03 后续：可载入 FM1 音色从 8 扩展至 21，全部通过原参数编译、整数模型/RTL 比对与 COM4 实板 PCM 检查。其余 107 条仍有明确缺项；默认只显示可载入音色，可取消筛选查看整库。

波表在停音期间收到按键起音时可能返回 BUSY，现已自动清理占用并重试原采样位置。用户停在 679 点的管风琴波表已完整续传，中途断线重连也成功；按键与音色配置保持不变。上传任务不再随页面销毁，暂停和中断不会丢失进度。完整证据和剩余缺项见 `FM1_WAVE_REPAIR.md` 及 `reports/fm1-wave-repair/`。本轮没有修改或重新烧录 RTL，仍使用上轮 50 MHz 固件。
