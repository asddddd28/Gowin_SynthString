# Voice 路由求和与命令校验优化

2026-11-02。时钟保持 50 MHz，采样间隔 1024 拍。基线为 `reports/fm-interpolation-pipeline`；以下 RTL 实验均开启 SDP32/36 拆分，与关闭拆分的 [RAM 对照实验](SDP_RESOURCE_EXPERIMENT.md) 分开。**三种 RTL 候选在完整物理结果中均退化，已全部撤回；42 个构建输入曾逐项核对恢复至通过基线，后续增益/声像分拍是另一个独立实验。**

## 两项改动

第一项为调制求和。基线最紧路径是 Voice 参数 RAM → `reg_operator_request[78]`，setup slack +0.015 ns。请求的 [95:64] 是调制输入；原实现按源索引串联条件加法。候选改为先选择六路有效 signed32 输入，再用 33 位两路和、34 位四路和、35 位总和构成平衡树，只在最终总和上饱和。所有源的符号扩展、正负抵消及索引 6/7 的旧组合语义均保留。请求仍在 state1 锁存，不新增状态或周期。

第二项为命令校验地址。在已有 `flag_packet_decoded` 拍捕获 8 位 `reg_check_address`，供下一拍的身份/业务校验、载波计数和提交格式检查使用。参数 RAM 写入、音色提交及其他真正的命令副作用仍使用握手时稳定的原始总线地址。采样 tick、音频非空闲、VALID 撤销或命令接受会撤销校验资格，下次重新捕获；没有新增校验阶段。

第二项针对命令头地址的高扇出和远距离布线。RAM 对照实验中，最紧命令路径的网络延迟为 15.517 ns，其中单条网络达 12.738 ns。寄存器局部化的目的，是把地址分发与后续深层校验分到已有的两拍。

新定向 TB 的严格门禁均为 0 错误、0 警告。主 RTL 历史紧凑格式及深组合锥等问题仍使严格门禁失败：基线 1546、加法树 1554、再加地址锁存 1566、仅地址锁存 1558 条错误。静态 compile 通过，AST 格式/可读性/注释/命名/profile 未通过；独立 xvlog/xelab/xsim 已通过。不能把功能回归通过说成完整风格验收。说明文档使用人工核对的显式契约生成；可选源端口扫描会把旧函数的局部输入误认为模块端口，错误日志已保留。

## 物理结果

| 指标 | 原通过基线 | 仅加法树 | 加法树 + 地址锁存 |
|---|---:|---:|---:|
| Fmax / MHz | 50.037 | 49.147 | 47.911 |
| 最小 setup slack / ns | +0.015 | −0.347 | −0.872 |
| Setup 失败终点 | 0 | 28 | 80 |
| Hold 失败终点 | 0 | 0 | 1 |
| Setup TNS / ns | 0 | −4.966 | −39.100 |
| Logic | 27110 | 27496 | 27439 |
| Register | 24090 | 24090 | 24098 |
| CLS | 24337 | 24654 | 24444 |
| BSRAM / DSP | 98 / 94 | 98 / 94 | 98 / 94 |

两种带加法树的候选都不采用。树形表达式虽然减少了源码中的串联求和层数，但不代表器件上的 LUT/进位链与布线更优。单独加法树反而增加 386 Logic、317 CLS，不能根据算法图宣称优化成功。

组合候选中，已展开路径到 `reg_prechecked_status` 的最小 slack 从基线 +0.047 ns 改善至 +4.117 ns；其中局部地址到校验寄存器路径为 +5.628 ns。同期路由调制仍有 −0.762 ns，DX 包络和 Voice 数据路径也失败。因此地址锁存值得独立验证，但上述局部收益不等于整板通过。

仅地址锁存的完整结果为 **46.363 MHz，WNS −1.569 ns，150 个 setup 失败终点，hold 失败 0，setup TNS −118.960 ns**。Logic27194、Register24098、CLS24327、BSRAM98、DSP94。虽然 CLS 减少10，局部地址路径改善，但整板不通过，亦不采用。

150个失败终点归属：VoiceSynthEngine102、AxisDxEnvelope32、AxisSchroederReverb16。Voice中 `reg_voice` → DSP A输入的27条失败路径实际经过 `wire_gain_sum`，不能仅凭DSP端点名称认定是音高乘法；增益平滑/调制前处理才是已观察到的数据锥。另有27条 `reg_voice` → `reg_mod_pan`、31条算子索引 → 请求、16条核心参数RAM → 请求以及1条音符查找结果 → 校验状态。后续优先尝试将平滑基础值预计算到已有声部准备拍，再执行调制叠加。

失败候选均保留源码、码流与报告用于复核，`result.json` 标记 `adopted=false`。**这些码流均未烧录，不应替代已通过的50.037MHz基线。**
