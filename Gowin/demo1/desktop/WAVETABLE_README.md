# 波表 RAM 热更新版

1. 关闭旧 App，先用 SRAM Program 烧录 output/demo1_wavetable_31004.fs 或 demo1_wavetable_31002.fs，选已经确认能通信的底板版本。旧 UART32 位流不支持上传。
2. 运行 release_wavetable/TangSynth32/TangSynth32.exe，连接板载 DEBUG USB 的 COM 口。
3. 点击“上传谐波钢琴表”直接体验：App 释放当前音符，暂时阻止新按键，上传并等待 FPGA 验证。成功后启用自定义波表及短起音、衰减至零的包络，保留原键位、音高、力度和音量。
4. 或点击“导入波表”，选择 JSON/CSV/TXT 文件。必须恰好 1024 个 -32768..32767 的整数，表示一个完整周期；JSON 可以是数组或包含 samples 数组的对象。不支持直接导入整段 WAV/MP3。导入文件完成后保留原 ADSR。
5. 进度达到 1024 后仍需等待提交确认；只有 FPGA 回报 CRC、token 和新一代编号匹配，才显示成功。上传超时或损坏时重新上传。提交应答丢失时可能已经切换，界面会提示结果未确认。

附带 tables/harmonic_piano.json 是静态谐波合成表，不是原声钢琴录音，也不含多采样或随时间变化的频谱。相邻半音的拍音仍会存在。

## 存储与声音

使用 FPGA 片上 BSRAM，1024×16 位一张表（2 KiB），活动区+备用区共 4 KiB。为两组引擎的 A/B 四个并行读取端口各保留一份，共 16 KiB，综合映射为 8 块 SDPB BSRAM；全工程 15/118 块。

一次只能启用一张自定义表，32 声部按各自相位共享读取。内置正弦/三角/方波/锯齿保留，下拉选择“自定义波表”使用 RAM。内部将 signed16 左移 2 位进入 signed18 振荡器，不改变原音高和 96.001 kHz 采样率。

写入仅针对备用区，顺序+CRC16 校验通过后，等待声音释放完的帧边界切换，不播放半张表。App 上传期间暂停新演奏；这是免重烧位流的热更新，不是持续按音符时无缝变换音色。

RAM 掉电丢失；KEY0 复位也清除有效标志。无有效自定义表时波形4回退内置正弦，重新上传即可恢复；App 当前不自动检测复位并重传。配置只保存波形选择与包络，不保存板上 RAM。尚未实现外部 PSRAM/SDRAM/Flash 持久化。

## 验证边界

GUI/协议/串口替身共23项测试通过；实际 UART RTL 仿真覆盖点序、CRC、完整度、ACK、空闲帧切换、复制RAM及复位。最终位流时序及硬件测试状态见 reports/wavetable_validation.json。尚未实际上传到板卡试听。静态严格风格门禁与功能证据独立，未声明 strict-ready。
