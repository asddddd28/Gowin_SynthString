# 驻留算子上下文与重复请求处理

2026-11-02。本轮在原 AXI 外设中接入 `AxisVoiceRuntime`，实现参数/状态驻留和最近执行结果重放。它是候选 Voice Engine 运行时的一部分，尚未接入板级演奏顶层或 App。

## 先区分三类“重复”

| 输入 | 应如何处理 | 当前工程情况 |
| --- | --- | --- |
| 实体键持续按住，扫描结果反复为 1 | 保存 Gate 状态，仅在变化时产生 NoteOn/Off | 板级使用的 `keyboard-studio/src/KeyboardVoiceBridge.v` 已比较 `i_pressed` 与 `reg_delivered` |
| 同一次请求因通信重试再次到达 | 按事务身份去重，返回原结果，避免再次改状态 | 本轮新增上下文执行序号和最近结果缓存 |
| 同一声部在下一采样继续计算 | 必须推进相位、包络、噪声等状态 | 每次合法执行使用新的序号；数值相同也不能直接丢弃 |

App 的 `StudioEditor.tsx` 已用 `!e.repeat` 忽略电脑键盘自动重复。实体键持续按住也不需要主机反复发送 NoteOn；当前固定引擎根据 Gate 和本地采样节拍持续计算。

同音高的第二次真实按下、琶音器产生的新音符、具有新身份的 MIDI NoteOn 都可能是合法事件，不能只按音符号或字节内容去重。没有事务序号的原始 MIDI 事件不能凭空获得可靠的重发身份；自定义传输层应在创建请求时分配身份，重传沿用它，新的事件才创建新身份。

目标事件与计算关系：

```text
键盘状态变化 → NoteOn → 分配声部/算子上下文、绑定参数
                         ↓
采样Tick → 执行程序 → RUN(seq0, NoteOn)
下一Tick → 执行程序 → RUN(seq1, Tick) → RUN(seq2, Tick) → …
键盘松开 → NoteOff → 对包络执行一次NoteOff，继续Tick直至释音结束
```

自动声部分配、程序执行和 Tick 调度尚待加入新运行时；本轮提供这些机制所需的独立状态和幂等调用基础。

## 当前实现与 hierarchy

```text
AxiVoiceEndpoint
└─ AxisVoiceRuntime
   ├─ 32项参数镜像 / 所有者代号 / 基础操作类型
   ├─ 32项独立递归状态
   ├─ 32项最近执行序号 / 精确实时输入 / 完成结果
   └─ AxisVoiceFabric（共享原计算池）
      ├─ AxisPhasePm
      ├─ AxisEnvelopeSegment
      ├─ AxisGainMix
      ├─ AxisNoiseStep
      └─ AxisEnvelopeMulti
         └─ AxisEnvelopeSegment
```

32 项是逻辑算子上下文容量，物理计算单元保持 PM×1、Segment×2、GainMix×1、Noise×1。参数镜像与状态分开存放，多个逻辑实例可以复用同一核心。此版本每个上下文各自保存一份参数快照，跨声部共享只读音色参数仍待 `ParamStore`/句柄化改造。

原始 opcode 0…4 的流式路径保持并发，仿真确认无阻塞接纳间隔仍为 1 拍。缓存操作先等待已有 raw 完成全部被消费，再独占缓存执行流程；同一时刻只有一个缓存操作在检查/计算/提交。它保证没有 pending 重发与状态写回竞争，后续可用每上下文 busy 位和事务表扩展不同上下文并行在途。

## 身份、缓存与一致性规则

| 字段 | 含义 |
| --- | --- |
| context_id | 8 bit 编号，当前仅 0…31 有效 |
| generation | 24 bit 上下文所有者代号，重用上下文时递增 |
| sequence | 每上下文 32 bit 执行序号，绑定后从 0 开始逐次加 1 |
| transport tag | 完整 32 bit 传输标签，只用于匹配本次响应，可以在重试时改变 |
| runtime signature | 精确保存 66 bit 实时输入；不使用可能碰撞的内容哈希 |

`RUN` 的处理顺序为上下文范围/有效性 → generation → 载荷格式 → sequence 与实时输入：

- 首次执行必须 sequence=0，之后必须等于最近已提交值+1。
- 相同 sequence、相同 66 bit 实时输入：返回缓存的结果，并设置 `replayed` 标志，不再次发射计算、不更新状态。
- 相同 sequence、不同实时输入：返回冲突。
- 更小 sequence：返回过期。每个上下文只保留最近一个结果，更早的结果不能重放，但也不会重新执行。
- 跳号：返回缺失序号错误，不跳过递归状态计算。
- generation 不符：拒绝。上下文被新的音符实例重用后，延迟的旧 NoteOff/计算包不能写进新实例。
- 复位清除有效位和在途任务。该保证仅适用于当前运行会话，不提供跨掉电的 exactly-once。上层必须重新建立会话、清理旧重发队列并重新绑定。

generation 和 sequence 不允许回绕复用。序号到最大值后要结束/重建实例，不能把 0 当成下一步。新的 generation 可以重新绑定；generation 达到最大值后的会话重建要在外部停止和清理旧流量后进行。

核心返回成功时状态与最近结果只提交一次，输出反压期间仅保持响应。重复请求若在首个请求尚未完成时入队，会等待它完成后命中最近结果；不会抢先开始第二次计算。成功重放仍产生一个 Completion，调用者照常读取并 POP，避免通信端等待不到确认。

## 新的操作与 AXI 寄存器

外部 AXI 地址、数据和 ID 位宽不变，ABI 次版本升为 `0x00010001`。原始操作及其载荷保持兼容；需要缓存语义时显式使用以下新命令。

| opcode | 操作 | 语义 |
| --- | --- | --- |
| `0x80…0x84` | BIND | 分别绑定 PM、Segment、GainMix、Noise、MultiEG；低 320 bit 是原核心的完整初始镜像 |
| `0x90` | RUN | 使用驻留参数和状态执行一次；低 66 bit 是实时输入 |
| `0x91` | INSPECT | 读取当前状态、类型及最近执行序号；payload 必须为零 |

`BIND` 对新的上下文或更大的 generation 建立参数并初始化状态。相同 generation、相同基础类型、完全相同 320 bit 镜像的 BIND 只回放确认，即使声部已运行也不会重置状态；同代号不同内容返回冲突，旧代号返回过期。

**BIND 是实例初始化，不是持续音参数热更新。** 后续需要单独的参数版本提交机制，在帧边界切换增益、频率、EG 参数并保留相位/包络状态；不能把旋钮每次变化都变成新 generation 的 BIND。本轮可实时传入 PM 调制值、MAC 输入和包络事件。

| 字节偏移 | 新增寄存器 |
| --- | --- |
| `0x01C` | 功能位图 7：bit0 驻留上下文、bit1 最近结果重放、bit2 状态观察 |
| `0x020` | 有效运算发射计数，排除重放 |
| `0x024` | 成功重放计数，包括重复 BIND |
| `0x028` | 拒绝计数 |
| `0x02C` | 新镜像绑定计数 |
| `0x030` | 当前上下文容量 32 |
| `0x134` | 暂存元数据：`generation[31:8] / context_id[7:0]` |
| `0x138` | 暂存 sequence |

两个新增暂存字支持 WSTRB，并随 `0x130 COMMIT` 与原 payload/opcode/tag 一起原子复制。命令 FIFO 从 360 扩为 424 bit；Completion 格式仍为 168 bit（opcode8/tag32/result128）。计数用于观察运行时行为，不能代替 Completion 作为任务完成确认。

`RUN` 实时字段：

| 核心 | word0 / bits[31:0] | word1 / bits[63:32] | word2[1:0] / bits[65:64] |
| --- | --- | --- | --- |
| PM | 本采样 modulation Q26 | 保留参与精确重试比较 | 保留参与精确重试比较 |
| Segment | 保留参与精确重试比较 | 同左 | 同左 |
| GainMix | 音频输入 a | 音频输入 b | 保留参与精确重试比较 |
| Noise | 保留参与精确重试比较 | 同左 | 同左 |
| MultiEG | 保留参与精确重试比较 | 同左 | 0 Tick / 1 NoteOn / 2 NoteOff / 3 Kill |

RUN 的 bits[319:66] 必须为零。即使某个核心不使用某实时字段，它仍属于请求身份，重试时不能更改它。从 BIND 切到 RUN 时要清空暂存区的保留位；后续只有实际变化的字段需要重写。

完成值：低 64 bit 为核心结果，bits[71:64] 为状态，bit72 表示成功重放。INSPECT 额外返回当前状态 bits[34:0]、历史有效 bit73、核心类型 bits[78:76]、最近 sequence bits[111:80]。其余位保留为零。

| 状态码 | 含义 |
| --- | --- |
| 0 | 成功；是否重放另看 bit72 |
| 1 / 2 | 原 Fabric 的未知操作 / 错误多拍包 |
| 3 | 无效编号或上下文未绑定 |
| 4 | 所有者代号不匹配或旧 BIND |
| 5 | 同执行身份或同绑定代号的内容冲突 |
| 6 | 执行序号已过期，超出单项重放窗口 |
| 7 | 执行序号跳号或首次未从 0 开始 |
| 8 | RUN 保留位非零或 INSPECT payload 非零 |

## 调用例子

PM 上下文 2，generation=7，初始相位 1，增量 3：

1. 写完整初始镜像，opcode=`0x80`，`0x134=0x00000702`，COMMIT，取回绑定确认。
2. 将暂存 payload 清为零，opcode=`0x90`，sequence=0，COMMIT → next_phase=4。
3. 即使更换 transport tag，重发 sequence=0、相同实时输入 → 返回 4，bit72=1，相位保持 4。
4. sequence=1 → next_phase=7。相同实时输入仍是下一次合法计算。
5. 重发相同 BIND → 只确认，不把相位改回 1。
6. 同 generation 下给 sequence=1 更换实时输入 → 冲突；给 sequence=3 → 跳号。

若实时输入与上下文未改变，后续一次 RUN 只需更新 sequence、tag、COMMIT 三个写数据字，而不必重传十二个参数/标签字。换上下文或改变调制输入时还需写对应字段。取回结果、POP 和 AXI 通道握手仍有开销。

## 资源、性能与下一步

表存储逻辑量为 `32×(320+35+24+3+32+66+64)+64 = 17472 bit`，约 2.13 KiB，另有读快照、接口寄存器和流水。这个数字不等于 Gowin 的物理 BSRAM 占用；宽度、端口、浅表深度和映射方式可能造成碎片，必须综合后验证。新增命令元数据另外让四项命令 FIFO 增加 256 bit。

本轮优化减少参数搬运和重复计算，尚不证明 FM6/目标复音满足每采样 1024 拍预算：缓存操作目前串行，外部仍逐基础操作收结果。下一步应继续：

1. 把参数按音色/版本共享，状态按逻辑实例独立；确定 RAM 字宽、银行和端口预算。
2. 加入复合 PM/FM Operator，在内部完成 EG→Phase→Sine→Gain，减少外部命令和完成记录数量。
3. 加入 VoiceAllocator、采样 Tick 和程序依赖表，让按键只创建/释放实例；持续音由本地运行时推进。
4. 加入每上下文 busy/提交表，让不同上下文并发；按最坏时延决定重放窗口是否需要多项。
5. 参数控制层合并尚未提交的旋钮更新，仅保留最后值；NoteOn/Off 等有次序的演奏事件不能随意合并。
6. 完成静态门禁、Gowin 综合/PnR，再接 App 自定义传输的会话/请求身份并上板。
