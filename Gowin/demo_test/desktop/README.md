# Tang Keyboard Lab

## 小游戏版（最新）

运行 `release_games/TangKeyboardLab/TangKeyboardLab.exe`，配合 `../diagnostics/keyboard_games/impl/pnr/keyboard_games.fs`。上方新增“小游戏”页，提供贪吃蛇、打地鼠、钢琴块三个入口和结束按钮。页面显示板卡回传的得分、倒计时、结束原因和4×8游戏画面。

**游戏逻辑全部在 FPGA 上运行。** App 只下发开始/结束命令并显示信息，没有本地游戏引擎、计分或方向控制。开始后关闭 App，板上游戏仍继续；重新连接检测到游戏模式时保留当前对局和板上校准，不自动重发校准打断游戏。首次下载仍需连接 App 下发32键校准。

- 贪吃蛇：绿色蛇、红色苹果。右下角T形四键为K23↑、K31↓、K30←、K32→，青色标识，四个控制格不属于活动区域。每个苹果10分；撞边界、控制区域或蛇身结束。吃苹果后逐渐加速，禁止直接反向。
- 打地鼠：3秒准备后计时60秒。绿色10分（1.6秒）、青色20分（1.2秒）、红色30分（0.9秒）。目标每0.6秒出现，按住不重复计分；漏按/按空不扣分，时间到显示总分。
- 钢琴块：上三行青色预告，底行绿色为当前目标；仅K25–K32参与判定，每次按一颗。正确后加1分并下移一行；按错或超时红闪结束。初始限时1.8秒，随分数提高缩短至最短0.5秒。

所有游戏有3秒准备时间；准备时请松开按键。结束提示闪烁2秒后熄灭，分数保留到下一局。点击“结束游戏”恢复所选普通灯效。仅切换App页面或关闭窗口不会停止游戏。SPI、按键迟滞和原四种灯效保留。游戏版新增CRC保护的 `#...` 状态帧，普通固件没有该帧时小游戏入口不可用。

以下说明中的 `release_reactive` / `keyboard_reactive.fs` 是保留的纯灯效版本；新游戏版也支持同样的校准和灯效操作。构建脚本默认输出 `release_games`。

Windows桌面应用，用于Tang Mega 60K keyboard固件的实时原始值监控、校准、按键位置显示和四种按键灯效。App采集校准端点，并把32键的端点、触发和释放阈值发送到FPGA；FPGA独立判键并驱动灯效。

## 启动与连接

运行 `release_reactive/TangKeyboardLab/TangKeyboardLab.exe`，保留同目录的 `_internal` 文件夹。选择DEBUG串口（本板为COM4，USB Debugger B序号2025030317B）后点击“连接”。固定115200、8N1、无流控；打开前将DTR/RTS设低，并连续排空2秒桥接旧缓存。随后查询固件、自动下发已有32键校准和选定灯效；所有命令逐条等待CRC应答，不发送调试器控制台命令或自动reboot。

板上需要运行 `../diagnostics/keyboard_reactive/impl/pnr/keyboard_reactive.fs`。它保留 `K01:ABC\r\n` 至 `K32:ABC\r\n` 原始数据，每完整扫描附带一次带CRC的板上按键状态。旧扫描固件仍可查看数据，但配置命令不会得到确认。SRAM位流和板上校准配置在断电后丢失；重新下载、连接App后恢复。不能同时运行其他占用该串口的采集程序。

矩阵为4行×8列，左上角K01，逐行到K32。卡片显示原始ADC、软件平滑后的归一化深度；新固件下绿色按下状态以FPGA回传为准。点击卡片可看该键最近12秒的曲线和端点。超过0.6秒未更新或断线会清除显示的按下状态。

## FPGA灯效

右侧选择灯效后点击“发送灯效”。“板卡确认”文字表示收到对应序号且CRC正确的应答；等待、超时、拒绝时不会声称已下发成功。

1. 单键亮约1秒：每键独立计时，多键可并行；长按不重复触发，松开再按可重启本键计时。
2. 彩色涟漪：以按下位置为中心，按格点距离向四周扩散并变色；新按键打断并从新位置开始。
3. 快速流水：选择从左到右或从上到下，按键触发整板快速扫过；新按键重新开始。
4. 十字扩散：以按下位置为中心，仅沿同一行、同一列向四个方向扩散；到边缘截断，新按键重新开始。

也可选择关闭。改变灯效会清除上一效果；保持按住的键需松开再按才触发新模式。RGB刷新50Hz，通道峰值32/255。模式保存在 `effects.json`，与校准同目录。

“下发32键校准”可手动重发。连接、应用校准、改变阈值、读取配置后会自动下发；必须全部32键有效才提交。传输先写备用区，32条全部确认后一次提交，失败保留原有效配置。成功提交清除按键状态和旧灯效。FPGA按原始ADC作迟滞判定，按下/释放均需连续两次扫描满足阈值，支持ADC随按下上升或下降。配置仅保存在FPGA易失存储器；关闭App后板上判键与灯效继续工作。

## 软件校准

1. 选择“全部32键”或“仅选中键”，保持目标按键全部松开，点击“1 采集松开位置”。采集2秒，样本不足、明显不稳定或数据中断时拒绝该轮校准。
2. 点击“2 记录按到底位置”。依次把目标键按到底并保持至少0.3秒，再松开，顺序不限。已采到有效终点的键显示勾号。若某键一直没有被计入，检查磁铁/机械行程、数据和信号变化量，不能直接跳过。
3. 全部目标键完成后点击“3 应用并保存校准”。未完成、取消或中断的候选数据不会覆盖原配置。

每键自动识别按下时ADC上升或下降，计算 `depth = clamp((filtered_adc - rest)/(bottom - rest), 0, 1)`，使用轻量指数平滑。零点用中位数；终点用7样本滑动中位数的最远有效位置，拒绝单帧尖峰和不足100计数的行程。实际按到底由操作人保证，软件不能判断机构是否抵达机械限位。

默认50%触发、35%释放，可设置不同阈值形成迟滞。释放阈值必须小于触发阈值。显示的0–100%是ADC端点归一化的相对位置；霍尔磁场/距离关系通常不是线性的，未经机械标定不能当作毫米位移或力值。

程序首次启动可载入随附“历史实测 · 2026-10-29”配置，它由本板已保存的全键按压数据和最后松开数据生成，来源写在JSON里，不是刚刚完成的新校准。你完成实时校准后会自动保存至 `%LOCALAPPDATA%/TangKeyboardLab/calibration.json`，后续优先加载它。装配、磁铁位置或板卡变化后应重新校准。也可用“保存配置/读取配置”交换JSON；无效文件不会覆盖原配置。

## 记录、回放与边界

- “录制CSV”保存接收时间、键号、原始ADC、软件深度、按下状态和数据源；断开或关闭时自动结束。
- “打开历史回放”读取已有 `.bin`/`.txt` 原始串口记录，明确显示“历史回放”，不代表当前硬件状态；回放模式禁止实时校准。
- 时间为主机接收时间，各键扫描并非同时发生；本工具不提供精确硬件延迟或跨键同步测量。
- 本版本未实现MIDI、音符发送、ADC精度校准、非线性位移标定或合成器控制。

## 开发与复建

Python 3.12（带Tk 8.6）与 `requirements.txt` 中的pyserial即可运行源码。打包使用PyInstaller 6.16.0。PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt pyinstaller==6.16.0
.\.venv\Scripts\python.exe app.py
.\build.ps1 -Python .\.venv\Scripts\python.exe
```

`build.ps1`先运行测试，再生成独立应用目录；默认输出 `release_reactive`。`keyboard_core.py`负责增量协议解析、配置、校准和显示状态；`board_protocol.py`负责CRC和逐条确认/重试；`transport.py`后台收发；`app.py`在Tk主线程更新控件。`make_measured_profile.py`可重新生成历史配置。

诊断参数：`--port COM4`启动即连接，`--diagnostics <json路径>`每秒记录运行状态，`--state-dir <目录>`隔离测试配置，`--replay <原始文件>`打开回放，`--quit-after <秒>`用于自动结束冒烟测试。错误日志在配置目录下的 `errors.log`。

串口行为依据：[pyserial API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html)；界面事件循环与线程依据：[Python Tkinter文档](https://docs.python.org/3.12/library/tkinter.html)。实板验证见上级 `reports/gui_validation.md`。
