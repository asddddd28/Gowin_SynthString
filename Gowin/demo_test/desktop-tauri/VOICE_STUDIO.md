# SynthString Voice Studio

FM1/DX 音色子集测试客户端，要求 `voice-system` 协议 5、ABI `0x00010005`。
旧 `SynthDebug` 页面仍保留在源代码中；不能用它控制此固件。

## 操作

1. 运行 `SynthStringVoiceStudio.exe`，选实际串口（当前为 COM7）。
2. 只有板卡刚复位或刚重新烧录时才勾选“建立新会话”。普通断开重连沿用本地会话。
3. 选择四个驻留槽：PIANO 2、ORGAN 1、BASS 3、BRASS 2。用鼠标琴键、电脑键盘 A/W/S/E 等或 MIDI 输入演奏。
4. Space 延音，Esc 紧急停止。旋钮上下拖动，Shift 精调，聚焦后可用方向键、滚轮，也可直接输入数值。
5. 编辑六个算子的输出电平、比率/固定频率、四段 DX EG；松键后提交，再重新起音。当前 L4 固定为 0，算法/路由沿用所选音色。
6. 128 条原厂音色可检索，只有首批四条允许装入任一驻留槽；其他条目提示尚缺功能或尚未验证。

实体键床独立工作，当前固定使用槽 1，音高 48..79。App 槽位选择只作用于其后产生的 App/MIDI 音符。
硬件输出使用底板 3.5 mm 音频口。主音量启动为 50%，并保留引擎固定复音余量。

## 会话与异常恢复

Rust 后台单独占用串口，所有命令按顺序发送。每次发送前将原始 52 字节请求及确认后的本地副作用写入
`%LOCALAPPDATA%/SynthString/voice-engine/COM7.json`，超时原样重试，成功确认后才推进序号。
若仍有未确认请求，点击“原样恢复请求”；不要仅为了重试勾选新会话。
Note ID 与输入源标识独立于音高；按住按键的重复输入不重复分配声部。断开与正常关闭会请求停止发声。
在未确认请求或断线情况下无法保证已送达停止命令，应恢复连接后紧急停止。

遥测由硬件回读；音色名称、编辑参数与版本由本机会话保存，并非 FPGA 参数反读。
不要同时使用 Python 诊断工具、旧 App 或其他程序操作同一个串口。
八声部可能共享一个音色，也可以分别使用四个驻留音色；这不是 128 个音色同时驻留。

## 构建与验证

运行 `build-voice-studio.ps1`：重新生成来自原厂库的参数和精确命令，构建前端，
以 `custom-protocol` 特性嵌入前端资源，生成独立运行的 Tauri/Rust 程序。
`cargo test --locked --manifest-path src-tauri/Cargo.toml --lib` 包含 CRC、响应匹配、参数范围、
四个音色与 Python 编译器命令逐字相等、未知结果持久化等测试。

`voice-probe.exe COM7 --fresh` 只在刚复位后运行，使用同一 Rust 后台做四音色、八声部、重复 NoteOn、
延音、参数提交、干声/FX、持久化重连和遥测检查；随后 App 应不勾选新会话连接。
命令会实际发声，请先调低外部监听音量。探测报告不替代 DAC 波形测量或人工听音确认。

原厂资源来源与许可证见 `FM1_NOTICES.md`；DSP 参考代码归属见 `DSP_NOTICE.txt`。
