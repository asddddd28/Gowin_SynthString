# FPGA 自主运行的 keyboard 小游戏

独立工程 `keyboard_games.gprj`，顶层 `KeyboardGames`。由已验证的 `keyboard_reactive` 扩展，保留其工程及B037位流。器件GW5AT-60B、50MHz，原ADC/键盘/RGB引脚不变，UART RX V14、TX U15。

## 职责

FPGA完成按键资格判定、随机目标、移动、碰撞、计时、计分、结束状态和RGB显示。App只发送开始/结束命令，显示校准、灯效设置、游戏画面、分数和时间。关闭App不会终止游戏；断电/复位则清除SRAM配置和游戏状态。

App路径：`../../desktop/release_games/TangKeyboardLab/TangKeyboardLab.exe`。位流：`impl/pnr/keyboard_games.fs`，下载到SRAM后连接COM4。首次连接自动下发保存的32键校准；若重连时板上已处于游戏模式，保持当前对局和校准。游戏页三个入口点击后有3秒倒计时。结束按钮恢复原选定普通灯效。

## 三种游戏

贪吃蛇：4×8格中的K23、K30、K31、K32作为T形方向区（上、左、下、右），不作为蛇的活动区域。蛇绿色、苹果红色、方向区青色。初始长度3，向右，每500ms走一格；每苹果10分并加快20ms，最短180ms。每步最多缓存一次转向，不能直接反向；若方向脉冲恰好与移动同一时钟沿到达，排到下一步。允许进入正离开的蛇尾。撞墙/方向区/蛇身结束，填满28格通关。苹果探测空格按每时钟一格进行。

打地鼠：3000个50Hz帧为60秒，每30帧尝试生成一个目标；不生成在已亮或按住的格子上。绿10分/80帧，青20分/60帧，红30分/45帧。按下边沿只得一次分，同时命中可累加，命中优先于同帧过期。最后计时边界之后不再收分，漏按/按空不扣分，记录漏按数。

钢琴块：每行一颗，顶三行青色、底行目标绿色；K25–K32可操作，其余键忽略。按对加1分，将全部方块下移并生成不与相邻方块同列的新顶行目标。按错或未在期限内按下结束。期限初始90帧，每2分减1帧，最短25帧。按下恰好在最后期限帧仍可命中。按住不自动连续触发。

错误红闪、正常结算/通关绿闪，2.5Hz共2秒后熄灭，分数保留。LED颜色通道上限32/255。50Hz整帧锁存，按键/游戏变化不撕裂正在发送的LED帧。

## 串口扩展

保留25字节 `!20HEX*CRC LF` 命令，CRC8/07、init0。原BEGIN/KEY/COMMIT/EFFECT/QUERY兼容。

| 命令 | 字段 | 行为 |
| --- | --- | --- |
| 0x41 | key=1/2/3 | 开始蛇/地鼠/钢琴块，要求有效校准，进入mode5 |
| 0x42 | mode=0..4，direction=0..1 | 停止游戏并恢复指定普通灯效 |

相同上一序号/载荷重传只返回原结果，不重复开始游戏。错误游戏编号返回03，无校准返回02。普通EFFECT或校准COMMIT也停止游戏；App在游戏模式下暂停自动校准同步，避免重连打断。

游戏状态：`#` +32位大写HEX + `*` +CRC两位+LF，共37字节。128位载荷高到低为：`game8, phase8, seconds8, reason8, score16, misses8, epoch8, pixels64`。CRC覆盖16载荷字节。每完整键盘扫描在原状态之后发送。像素K01对应bits1:0，K32对应63:62，0灭、1绿、2红、3青。

phase：0空闲、1倒计时、2进行中、3结算/失败、4通关。seconds在准备阶段为倒计时、地鼠为剩余时间、蛇/钢琴块为已用时间（饱和255）。reason：0正常到时、1撞边界/控制区、2撞蛇身、3钢琴错键、4钢琴超时、5主动结束、6填满蛇活动区。epoch每次新开始加1，用于确认重连及幂等重试。

## 文件与验证

- `src/GameEngine.v`：所有游戏规则。命中分数和到期数量使用平衡加法树。
- `src/GameDisplay.v`：锁存整帧游戏图像和LED来源选择。
- `src/KeyController.v`：增加开始/结束命令，仍负责校准与按键。
- `src/KeyboardTelemetry.v`：串口逐记录仲裁，原始ADC、ACK、普通状态、游戏状态。
- `game_model.py`：独立Python规则核对；不在App运行。
- `sim/tb_game_engine.v`：倒计时、蛇生长/转向/碰撞/尾部/满盘、三色分数/多点命中/过期/持键排除、精确3000帧地鼠、钢琴移位/错误/超时、灯光整帧与复位。
- `sim/tb_keyboard_games.v`：实际UART位流、128位状态CRC、幂等开始、ADC采样校准后的钢琴命中/错误/结束。通过198次游戏状态及6336条原始ADC记录。
- `reports/python_tests.log`：35项Python/Tk测试；包含混合串口分片、坏CRC、界面分数来源和重连不打断对局。
- `reports/build.log`：Gowin构建；优化后fMax54.865MHz，50MHz无违例；5338逻辑单元、2148寄存器、6.5DSP。
- `verify_board.py`：真实串口验收脚本；开始地鼠后主动关闭串口5秒，再打开验证同局倒计时继续推进。要求刚下载的未配置板卡、空闲COM4。
- `reports/program_sram.log`：下载Finished，User Code7C30、Status76026238，仅SRAM；没有全量回读验证。
- `reports/hardware_serial.json/.bin`：实际校准、无校准/错误编号拒绝、开始重试不重启；231个游戏状态CRC全部正确。关闭串口5秒后重新接收，同一epoch1的倒计时从60降至53（包含重开接收时间），证明无需App推进游戏。跨主动断开的2次键序不连续单独记录。
- `reports/gui_live.json`、`gui_physical_session.jsonl`：打包App重连仅发送QUERY（25字节），保留mode5、校准generation1与游戏epoch1；板上完成一分钟后回传phase3、剩余0秒。UI没有重发校准或重开游戏。玩家操作体验以 `physical_playtest.json` 中的用户反馈为准；该文件不存在时仍待确认。

`contract.json`及`spec/src`保存10个模块说明/时序示意。严格风格门禁仍未通过（1614条，含端口归一化失败引发的检查链失败），不能宣称符合其完整规范；真实编译、仿真、时序和实板验收分别记录。现有EX3791色相受限累加位宽提示及PR1014输入时钟通用布线提示保留。模拟信号精度、串扰及仪器级时序不属于本次游戏验收。

复建：在此目录执行 `gw_sh.exe build.tcl`。xsim在sim目录中显式列出src文件进行xvlog，再分别xelab/xsim `tb_game_engine` 和 `tb_keyboard_games`。以PASS内容而非进程返回码判定仿真。
